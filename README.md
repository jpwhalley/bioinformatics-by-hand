# Interactive Bioinformatics Module

Eight self-contained, browser-based sections that teach bioinformatics as one
repeated operation: **matching one set of letters against another, at scale, and
interpreting the result.** Built for GMIC605 Molecular Biology Techniques at
Rosalind Franklin University of Medicine and Science.

**[Open the module](https://jpwhalley.github.io/bioinformatics-by-hand/)**: it
runs entirely in the browser. Or download the repository, keep the files
together, and open `index.html` locally; nothing needs a server.

## What it is

A replacement for a lecture. Each section is a single HTML file that runs
entirely in the browser: no installation, no login, no server, no network. The
student does the work rather than watching it, and every section ends on a
judgement they have to defend rather than a fact they have to recall.

| | Section | The match it makes |
|---|---|---|
| 1 | Sequence alignment by hand | One 12 base read against a 40 base reference, moved by hand |
| 2 | Searching a database with BLAST | One human sequence against six species, scored |
| 3 | Reading a FASTQ file | An adapter stub against the end of a read, and an index against a sample sheet |
| 4 | Running a sequencing pipeline | Thirty million reads against three billion bases |
| 5 | Which variant matters | Variants against a population catalogue, a conservation score and an annotation |
| 6 | Functional genomics and quality control | Reads against the genome, then the pile around every start site against the background |
| 7 | Functional genomics and analysis | An RNA read against a genome that still has the intron, then a gene list against gene sets |
| 8 | A new assay | A cell barcode against a whitelist, a UMI against the other UMIs, cDNA against the genome |

Section 8 opens on a collaborator's claim about single-cell RNA-seq data, an
assay the module never teaches, and ends with the student building the
checklist they will use on the next unfamiliar assay.

The sections do not run in the order the laboratory does. Alignment comes first
because it is the idea everything else is built on; the raw data comes after.
`index.html` sets both orders out side by side and says why.

## What a student does

Work through the sections in order and complete the main route in each. Panels
marked "Go deeper" are optional; skipping them leaves no gap.

Each section builds a **lab notebook** from the student's own decisions, which
they can download as a text file. Nothing is uploaded, submitted or saved
automatically: the notebook exists only in the open page, so it has to be
downloaded before the page is closed.

There is no clock and no score.

## The data

**Everything in this module is simulated.** All reads, quality scores,
genotypes, family structures, peak counts, expression counts and cells are
generated by seeded simulations inside the pages themselves. They are built to
reproduce selected characteristics of real experiments, and they contain no
donor data.

Where a section quotes a real number, it is a published one, cited in the page:
NCBI's BLAST statistics, ENCODE's ATAC-seq standards, 10x Genomics' read
structure, and the papers named in each section's "go deeper" panels.

`index.html` sets out what simulation preserves and what it takes away, because
that is itself one of the things being taught.

## Accessibility

Built to **WCAG 2.1 Level AA**, and tested rather than asserted:

- axe-core against every section at 1280px and 320px, after a script has driven
  each page through its interaction states: **no automated violations**
- 82 manual checks for the criteria automation cannot see: focus order, the
  keyboard route to every value, live-region behaviour, reflow and text spacing
- every SVG text node measured for contrast against its nearest painted
  ancestor, with the large-text exemption applied: 114 nodes, all clear

Everything is operable from a keyboard, including the drag-and-drop alignment in
Section 1 and the gap placement in Section 3. Nothing depends on colour alone.
Figures are live SVG with text alternatives, not images.

**The honest gap:** none of this has been tested with a real screen reader,
voice control or switch access. The audits above are a developer checking his
own work with a machine. If you use assistive technology and something here does
not work, that is worth telling me about.

## Technical notes

- Each section is one file. Inline CSS, inline JavaScript, no dependencies, no
  CDN, no build step, no analytics, no cookies, no storage.
- Simulations are seeded, so every student sees the same numbers and the pages
  agree with their own prose.
- Tested under jsdom and in Chromium. The behaviour tests, design notes and
  prototypes are kept outside this repository; this is the built module.
